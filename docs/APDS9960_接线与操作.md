# 数芯天下 v7.8：APDS-9960 手势控制

在保留的 v7.7 中文版上增加手势功能，原按键、字幕、音乐、频谱、缩放和透明度保留。
FPGA 自行完成 I²C 驱动、原始 U/D/L/R FIFO 读取、方向识别和播放器控制，无需 STM32、ESP32 或 Arduino。

## 接线（断电后操作）

| APDS-9960 模块 | HX4S20C 开发板 | FPGA 管脚 |
|---|---|---|
| SDA | J2 第 1 脚（GPIOB_0） | P4 |
| SCL | J2 第 2 脚（GPIOB_1） | N4 |
| VCC | J2 第 29 脚，3.3V | 电源 |
| GND | J2 第 30 脚 | 地 |
| INT | 不接，使用轮询 | — |
| VL | 按模块说明确认红外 LED 供电，见下文 | — |

J2 编号来自本机 HX4S20C 原理图；先认准排针旁的 J2 和 1 脚标记，核对板卡版本后接线。
J2 第 11 脚是 5V，不要与第 29 脚混淆。信号使用 3.3V 电平。
SDA、SCL 需上拉到 3.3V：模块已有上拉时不重复添加，没有时各用约 4.7kΩ。不要只依赖 FPGA 内部弱上拉。
建议使用短杜邦线，先完成接线再给开发板上电。

VL 不是通信脚，通常是红外 LED 的独立供电输入。若模块已通过跳线连接 VCC 与 VL，无需另接；若是独立 LED 电源输入，应按该模块原理图接适当电源，常见 APDS-9960 模块可用 3.3V。
本次未拿到这块商品模块的电路图，不能仅凭型号断定 VL 已内部连通。未确认前不要盲接 5V；红外 LED 未供电会导致 I²C 初始化成功但没有手势。

## 下载与操作

1. 用 TD 下载 MuseumGuide_Gesture_v7_8.bit。TF 卡 BMP、MUSIC.WAV 和字幕素材无需更换。
2. 观察 HDMI 左上角面板右侧的小色块：绿色表示芯片 ID 检查及寄存器初始化已成功，红色表示离线／尚未初始化；这不代表红外 LED 供电或识别效果已验证。色块仅在 OSD 打开时显示。
3. 模块感光面朝向手掌，先在约 5～10 cm 距离平稳挥手，挥完后移开。这个距离是调试起点，实际范围受模块、环境光和安装方式影响。

| 手势 | 操作 |
|---|---|
| 左挥 | 下一张图片 |
| 右挥 | 暂停／继续图片自动轮播，音乐继续播放 |
| 上挥 | 缩放循环：100% → 50% → 75% → 100% |
| 下挥 | 图像效果循环：原图 → 增强 → 轮廓 → 海报 |

方向按传感器的 U/D/L/R 轴定义，模块旋转或翻装会改变与屏幕方向的对应。若方向不一致，先调整模块安装方向；也可反馈实际方向再修改映射。
一组有效手势至少四个样本；弱信号、静止、来回返回原方向、斜向歧义会被过滤。结束后等待约 80ms 确认，再发一个操作；约 350ms 冷却用于防止重复操作。
缩放沿用原来的图片加载流程，会暂停轮播，加载期间可等待当前操作完成。多张图片时才可切换自动轮播。

原按键仍可使用：KEY1 下一张，KEY2 自动轮播；KEY3 短按切效果，长按 1～2 秒切焦点框、2～3 秒切 OSD、至少 3 秒切不透明度。
按住 KEY3 点按 KEY1 调亮度，点按 KEY2 调缩放。

## 无响应时

- 色块一直为红色：先核对 J2 插针、3.3V、共地、SDA/SCL 是否接反和上拉；软件会自动重试。仅接受芯片 ID 0xAB、0x9C（I²C 地址 0x39）。
- 色块为绿色但没有手势：优先确认 VL/红外 LED 供电、感光面朝向和手掌距离；避免强烈阳光直接照射。不要先改动已验证的 HDMI/SDRAM 时钟。
- 一次挥手只执行一次，手移开后再做下一次；斜着挥、只靠近不横移或幅度太小可能不会触发。
- 传感器缺失、NACK、总线卡死或 FIFO 溢出时，不会阻塞播放器。溢出/通信错误会丢弃未完成手势，恢复后再识别。
- 不接传感器也能继续用原按键。需要回退时，下载原 MuseumGuide_Chinese_v7_7.bit。

## 验证边界

软件仿真和 TD 实现结果见 verification.json。
独热状态的并行解码会产生 HDL-5007 综合提示；40 种唯一状态赋值形式均只赋单个状态位、在两个单状态中选择、复制独热返回状态或保持，因此从复位归纳保证状态独热。21 项额外仿真也启用了独热不变量检查，依据保存在 verification/scaler_one_hot_proof.json。尚未通过实物传感器和开发板测试，方向、距离、灵敏度及长时间运行需上板确认。
时钟频率及正常运算路径的时序要求与 v7.7 相同。约束仅修正两类已有同步结构对应的 CDC 例外：startup_done 经异步复位入口到同步释放链的路径，及视频域效果编号到 50MHz 数码管状态同步器的首级采样。后者的第二级寄存器仍正常检查，100MHz 音乐/缩放/存储数据路径没有被排除。审计依据见 verification/cdc_constraint_audit.json。原 SDRAM 硬宏位置和局部时钟布线告警仍需结合实板验证。
为接入后的时序收敛，缩放控制改用显式独热编码，双线性水平乘法与加法拆为两拍，目录项的簇有效性提前一字节计算；音乐 FIFO 的保守空间判断增加一级寄存器（为最多 256 字的扇区预留 512 字空间，保留安全余量）。像素公式及舍入规则不变，31 项双线性和 14 项最近邻像素检查已重新通过；有效图像区域每像素增加一拍，实际载入时间需实板测量。图片素材格式和 MUSIC.WAV 要求沿用 v7.7。

复现构建：在工程根目录运行 Python 的 tools/build_td.py。脚本沿用 v7.7 的综合配置及 normal 布线设置，具体记录保存在 verification/build_strategies.json，实际 Tcl 流程也随源码提供。失败的优化策略尝试留在 verification/attempt_* 目录用于追溯，最终结果以根目录 verification.json 和 verification/final_timing.rpt 为准。软件安装路径可按本机位置调整。

依据：[APDS-9960 厂商数据手册](https://cdn.sparkfun.com/assets/learn_tutorials/3/2/1/Avago-APDS-9960-datasheet.pdf)，[SparkFun 参考驱动的器件 ID 定义](https://github.com/sparkfun/SparkFun_APDS-9960_Sensor_Arduino_Library/blob/master/src/SparkFun_APDS9960.h)。
本工程 RTL 为新的 FPGA 实现，没有运行上述 Arduino 库。

最终建立裕量 +0.102 ns，保持裕量 +0.003 ns；建立／保持违例端点均为 0。
